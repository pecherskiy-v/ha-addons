# Agentmemory

Общая память агентов: движок `iii` плюс пакет `@agentmemory/agentmemory`.
Состояние — в `/data/state_store.db` внутри тома дополнения.

## Порты

- **3111** — HTTP API, сюда смотрит `AGENTMEMORY_URL` на клиентах
- **3112** — поток событий

## Почему собирается на месте, а не берётся готовый образ

Официальный `iiidev/iii` — distroless-образ одного движка. Последний воркер в
его конфиге запускает `node dist/index.mjs`, то есть без Node и кода пакета
сервис неполон. Плюс distroless не даёт поправить права на томе: в их
`docker-compose.yml` для этого предусмотрен отдельный init-контейнер, которого
в дополнении быть не может. Поэтому образ собирается из базового HA-образа с
Node и пакетом из npm.

## Что делает run.sh

1. Подменяет `iii-config.yaml` на `iii-config.docker.yaml` — первый слушает
   `127.0.0.1` и снаружи контейнера недостижим.
2. Создаёт `/data/.agentmemory` и при первом запуске — `.env` из шаблона.
3. Запускает CLI `agentmemory`, который поднимает движок и воркер.

## Перенос данных с этой машины

Состояние — один файл, 321 МБ:

```bash
# остановить дополнение в интерфейсе HA, затем:
scp ~/.agentmemory/data/state_store.db ha@<адрес-HA>:/tmp/
ssh ha@<адрес-HA> 'sudo mv /tmp/state_store.db /usr/share/hassio/addons/data/<slug>/state_store.db'
```

Точный путь тома покажет `ha addons info local_agentmemory`.

## Файловая память Claude Code — это другое

`MEMORY.md` и файлы рядом с ним Claude Code читает с диска и подгружает сам в
начале сессии. Это дополнение их не заменяет и общими не делает: нужен либо
отдельный механизм синхронизации файлов, либо перенос их содержимого сюда.
